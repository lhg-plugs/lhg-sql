# /lhg-sql:sql —— 中文取数一条龙

用户输入在 `$ARGUMENTS` 中：`<业务问题中文描述>`，`--方言` 缺省为 MySQL。

## 流程（全程按 skill 方法论执行）

### 第 1 步：澄清业务问题（加载 lhg-sql-ask 第 2 节）

把用户的一句话翻译成"取数五要素"并跟用户确认：

| 要素 | 示例 |
|---|---|
| 取什么 | 订单金额、用户名 |
| 从哪取 | orders 表、users 表 |
| 什么范围 | 近 7 天、状态=已支付 |
| 怎么算 | 求和 / 计数 / 明细 |
| 怎么排 | 按时间倒序，取前 100 |

**拿不准的不猜**：表名、字段名、口径（如"近 7 天"含不含今天）必须跟用户确认，不许编表名。

### 第 2 步：理解表结构

- 让用户提供表结构（`SHOW CREATE TABLE` / 建表语句 / 数据字典截图转文字）。
- 没有表结构 → 先停下来要表结构，不许凭空编字段。
- 输出"表结构卡"：表名、字段名×类型×含义、主键、外键关联。

### 第 3 步：生成 SQL（加载 lhg-sql-ask 第 3 节）

按"先 SELECT 验证，再写最终版"的顺序：

1. 先写最小验证 SQL（`LIMIT 10`），确认字段与关联正确
2. 再写完整 SQL：显式列名、JOIN 写法、WHERE 条件、排序、LIMIT
3. **SELECT * 禁止**；UPDATE/DELETE 必须带 WHERE（先 SELECT 验证影响行数）

### 第 4 步：方言适配（加载 lhg-sql-dialect）

按 `--方言` 检查：日期函数、字符串拼接、分页写法、类型转换是否用了其他方言的专有函数。跑一遍对照表，逐项打勾。

### 第 5 步：权限与性能自检（加载 lhg-sql-perf）

```
python3 <插件目录>/scripts/audit/sql_audit.py --target <SQL文件目录> --dialect <方言> --format text
```

- blocker（缺 WHERE 的 UPDATE/DELETE、DROP/TRUNCATE、SQL 拼接）→ 必须修
- warning（SELECT *、全表扫描、前导 LIKE、N+1、无 LIMIT、方言误用）→ 修或写理由
- 大表查询：提醒用户先看执行计划（`EXPLAIN`），不在本插件内代跑

### 第 6 步：交付

输出顺序：**取数五要素确认 → 表结构卡 → SQL（验证版+最终版）→ 方言检查结论 → 审计报告**。
每段 SQL 配一句话中文解释（"这段查的是…"），让小白能看懂、敢执行。

## 硬规则

- 编表名、编字段名 → 不许。没有表结构就停下来要。
- 生成 UPDATE/DELETE 不带 WHERE → 不许，审计脚本会判 blocker。
- 为清零改审计规则 → 作弊，不许。
